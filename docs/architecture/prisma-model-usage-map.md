# Prisma model-to-application map

**Snapshot:** `main` at `c259e7cd68ed63ce239e3fdf9f9913296b74e87e` plus the current working-tree changes, including the modified `prisma/schema.prisma`. This map does not describe the earlier 42-model snapshot at `6b9836a03b10b0ef0059854d77f120f17a11dc38`.

## Scope and method

- Model names, physical table names, and declared relations are extracted from the current `prisma/schema.prisma`.
- Direct Prisma Client and transaction-client delegate calls (`prisma.<model>.<operation>` and `transaction.<model>.<operation>`) were scanned in `app/`, `components/`, `features/`, `lib/`, and `actions/`. Repository/service callers are traced to API handlers and server-rendered pages; UI files referencing matched API URLs are listed where found.
- Nested relation reads are reported separately from direct delegates. Raw-SQL table references are matched to physical table names and reported separately.
- This is a static inventory, not runtime proof. Missing direct calls do not prove a model is unused; dynamic SQL, dynamic imports/URLs, seed code, tests, migrations, and external services may not be represented. API/UI presence does not prove schema compatibility.
- File paths are current working-tree paths; line numbers are omitted so the map remains readable as source files evolve.

## Snapshot findings

- The schema defines **136 models**. `ProductImage`, `ProductPriceHistory`, `Shipping`, and `ShippingMethod` are not model names in this snapshot. Related current models are `ProductMedia`, `ProductPrice`, `ShippingCarrier`, `ShippingService`, `ShippingZone`, `ShippingRate`, and `Shipment`.
- `PasswordResetToken` and `VerificationToken` are used by token repository flows; their API mappings below distinguish the two token purposes. `Role`, `Permission`, `RolePermission`, and `UserRoleAssignment` now back platform-scoped control-panel RBAC: custom roles link allowlisted permissions, and assignments are checked on protected routes. Seller-scoped RBAC remains outside this implementation.
- Delegate-shaped calls were found for **28 / 136** models in runtime source. This includes transaction-client calls; relation reads and raw SQL are counted separately.

## Reading the map

- Direct delegates are persistence calls. A nested relation is access through the parent model, not an independent CRUD/API surface for the child model.
- API routes, pages, and UI callers are statically traced and may be missed when imports, query construction, or URLs are dynamic. A listed endpoint may still query an older data shape.
- Use declared relations to decide ownership and workflow boundaries; do not build CRUD pages solely because a model lacks direct access. The earlier `docs/PROJECT_AUDIT.md` scan reports a different checkpoint count and did not count transaction-client delegates the same way.
